### [P1] home-1: Arabic Fantasy countdown shows 4 minutes as 40
- Verified: confirmed (was P1). Real shipping code, and I reproduced it myself. Intl.NumberFormat('ar-MA') returns Latin digits, so padStart(2,'٠') builds a string that mixes U+0660 with U+0034. In the Arabic line it renders as 4 then ٠, which reads as 40 minutes. French correctly shows 04. This breaks the documented rule (PRODUCT.md Accessibility: Western digits in both languages, kept left to right). It is not recorded as [Inconsistent]. I kept P1 because this is the number Fantasy managers act on. The absolute deadline time is printed on the same line, which softens it a little.
- Screens: home, home-out
- Evidence: src/components/fantasy/DeadlineStrip.tsx:33 pads the minutes with an Arabic-Indic zero ('٠'), while the number formatter already returns ordinary digits for ar-MA. So 4 minutes becomes '٠4', which displays as '4٠' inside an Arabic line. A live check with the clock moved forward 55 minutes showed 'بقي 37 س 4٠' (agents/home-A/strip-ar-zoom.png). French shows '37 h 04'. The synthesis confirmed the same pad in src/components/fantasy/DeadlineCard.tsx:41. The detector did not catch it, because no pattern rule reads digit order.
- Why: For the first ten minutes of every hour, an Arabic manager reads the Fantasy deadline as 36 minutes further away than it is. It is the one number people act on, and it breaks the product's own rule of ordinary Western digits in both languages.
- Fix: Pad with the ordinary '0' in both languages, or ask the number formatter for two digits. Keep the time-left part reading left to right inside the Arabic sentence. Make the same change in the deadline card, and add a test for Arabic with fewer than 10 minutes left.
- Command: /impeccable harden
