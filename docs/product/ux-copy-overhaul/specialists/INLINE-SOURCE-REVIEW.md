# Inline/source-only copy review

Read-only follow-up to sports editorial review. Output: `/tmp/botolago-inline-proposals.json`, 88 exact source replacement pairs with path/original/replacement/reason/lang. Every original string/snippet was verified to exist in its current source. No repository or database edits and no tests claimed.

Scope: source scan of public routes and metadata, common/loading/error/unavailable/offline primitives, shell, i18n bootstrap fallback, public OAuth consent error, fatal render page and native offline HTML, admin route guards, security/staff/approvals/audit/users/news/article/new article, Plus/member/payment administration, player matching and bulk review copy, SofaScore player queue, Prospects editions/data/photo approval administration, stories editor, related copied user-facing error dictionaries under backend. `/tmp/botolago-inline-source-coverage.json` records candidate source files discovered by this scan (source coverage, not verified browser access). All routes are included even where admin access cannot be opened in the browser.

Main findings:

1. Fatal rendering failure is entirely English, outside i18n; propose static French/Arabic recovery copy that still works when dictionaries and JavaScript fail. Native offline fallback already contains proper French and Arabic and needs no domain change.
2. Consent error directly prints provider Error.message in public UI. Reusing the existing generic translated error avoids backend/English leakage; keep logs or bounded diagnostic details separate. A future classified actionable error mapper would be better than raw provider prose.
3. Admin staff/security contain literal English MFA and queue values, and “principal”, “AAL”, “worker service-role”, “payload Auth” and migration-number prose. Proposals preserve queue counts, security states, role boundaries, immediate access blocking versus requested provider revocation, and operational recovery actions.
4. User administration unavailable copy names a specific migration and guarantees functionality after application. The general outage/error condition does not support that promise. The replacement asks the responsible technical operator to investigate.
5. Prospects publish confirmation promises the email goes immediately to subscribers. Delivery depends on configuration and separate dispatch; the proposed text preserves public publication and makes dispatch conditional.
6. Player-mapping approval text claims nothing is written until execution. Approval itself is persisted; correct distinction is approval is saved while association is created only after separate execution confirmation. All reviewer, self-approval, exact fingerprint, provenance, confirmation phrases, and guarded transaction constraints remain unchanged.
7. Empty SofaScore queue says everything is up-to-date. An empty queue proves only that no rows await confirmation; it cannot establish freshness of every football data surface.
8. Arabic ranking-calculation prose confuses الحساب as a user account; use عملية الاحتساب. Arabic photo fallback says shadow; use الصورة البديلة without changing private photo/release approval behavior.
9. Shared Dialog/Sheet say Close to screen readers; shared pagination is also in English. JSON provides a static bilingual copy-only fallback, but root should prefer existing locale keys with useI18n when modifying component plumbing. Mounted public reachability of pagination is not established; Dialog/Sheet usage should be checked by root.

Appropriate technical detail retained deliberately: provider names in player identity review, evidence classes, hashes/fingerprints, supporting mapping dependencies, exact confirmation phrases, staff reason-length requirements, roles/permission values, security codes shown as a diagnostic reference, true queue processing states, guarded one-row execution, photo rights/signed releases and the named GitHub workflow operators must actually run. Removing these would weaken decisions. Frozen manifest prose and fixture/sample data are excluded.

Metadata review: public descriptions are mostly plain already; news metadata's “Toute l'actualité” is an unsupported exhaustive claim and can become “Actualités”. Current metadata is rendered in French by the existing language architecture; adding Arabic metadata routes is out of copy-only scope.

Do not bulk replace words such as “officiel”, “source”, “calcul”, “provisoire”, “permission” or “fournisseur” across the codebase. Their meaning is necessary in scoring rules, licensed reporting, data methodology and administration. None of this review authorizes changing deadlines, scoring, squad rules, entitlement checks, payment details, retention/legal terms, evidence approval rules or runtime behavior.
