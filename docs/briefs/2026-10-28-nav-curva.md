# Navigation: Curva for members, Prospects for everyone else (screen brief)

Owner-approved design-critique fix, 2026-10-28. Branch `claude/dc-nav-curva`.
Scope: the fifth slot of the bottom bar and of the desktop top-bar links
(`src/components/shell/primary-nav.ts`, `BottomNav.tsx`, `TopBar.tsx`,
`PendingScreen.tsx`, `SectionWarmup.tsx`), and the back link in the Prospects
home header (`PepitesHome.tsx`, title band only).

**Owner decision 2026-10-28: Curva is for signed-in members only.** It
supersedes the 2026-10-08 plan in which Curva took the fifth slot for every
reader while it was live (`docs/product/MANAGER_CARD_SECTION_PLAN.md` 3.3).

Finding (critique, P1): "Curva bottom-nav tab is a padlock for signed-out
visitors; Prospects buried under Fantasy." A visitor's fifth tab opens a
blurred page with a padlock (`curva-mob-fr-light-full.png`), while the Prospects
(Pépites) section, which a visitor can read in full, is reachable only through a
tile inside Fantasy and opens with a "← Fantasy" back pill, so it reads as a
sub-page.

Related open pull requests checked: #540 ("a clear way out of Curva") touches
the Curva guest hero and sign-up only, none of these files; #578 touches
`FirstLaunchLanguage.tsx` and two new shell files, not the navigation. No
overlap, nothing ported.

## What must be preserved

- The bar's design: five equal tabs, the sliding action-gradient pill, the
  second cue (heavier label), `aria-current`, 44px targets, the micro type,
  the height `--bottomnav-h` is computed from (76px French, 82px Arabic).
- The order Accueil, Matchs, Fantasy, Actualités, then the fifth slot; Profil
  in the top bar. Pronostics keeps lighting Matchs.
- For a signed-in member while Curva is live: the fifth slot is Curva exactly
  as today, Fantasy lit on `/pepites/*` (Prospects lives inside Fantasy for
  members), the « ← Fantasy » back pill on the Prospects home.
- "Live" still means both layers (`MANAGER_CARD_BUILD` and the database
  status read on the server). Build switch off: no hook, no query.
- `/curva` for a signed-out visitor keeps its gate (the lock screen, and
  nothing drawn until the session is known). Fantasy, the Curva routes and the
  Manager Card business rules are untouched.
- French and Arabic, RTL through logical properties only, Latin digits.

## Improvements

1. The fifth slot follows who is looking:
   - signed out (or session not known yet): **Prospects** (`/pepites`, "Prospects"
     / "المواهب", the existing `nav.pepites` key, the `Gem` icon already used for
     it);
   - signed in and Curva live: **Curva**, as today;
   - signed in and Curva not live: Prospects (as today).
2. One rule for "who has Curva in the bar", `curvaInBar = live && authenticated`,
   shared by the bar, the desktop links, the pending screen and the warm-up, so
   the active tab is always one that is actually in the bar:
   - `/pepites/*` lights Prospects for a visitor and Fantasy for a member with
     Curva in the bar; `/curva/*` lights Curva only when it is in the bar;
   - while the session loads the visitor set is drawn (the server render and
     the first client render agree, no hydration mismatch); the tabs have the
     same size either way, so a member's fifth tab changing from Prospects to
     Curva moves nothing.
3. The Prospects home shows its back pill only where Prospects is not a tab:
   a member with Curva in the bar (« ← Fantasy », unchanged). Visitors, and
   members while Curva is off, get the title band without it.
4. Curva stays unreachable from the visitor navigation: no tab, no desktop
   link. A direct visit to `/curva` still gets the lock screen.
5. The top bar's Profil icon appears whenever the bar itself does not hold
   Profil (it used to be tied to Curva being live, which would now double it
   for a visitor in the edge case where Prospects is switched off).

Owner direction 2026-10-28 ("do not make pages too pale, more alive, on
brand"), as it applies to the bottom menu: the active tab stays clearly lit with
the existing fresh-turf-to-sky pill (`--ui-grad-action`, heavy label, ink-deep
icon), and the bar does not get greyer: no change to its surface, tone or
inactive-label colours, and the new Prospects tab uses exactly the same states
as every other tab. Nothing else in this lane changes visually; the screenshots
show the pill on Prospects for a visitor and on Curva for a member.

Decision the owner can flip: the visitor's fifth tab is Prospects. The
alternative is Classement (`/matches/standings`), but that is already inside
Matchs, so it would add a second door to a page the bar already reaches.
Flipping it is small: the `/pepites` entry of `allPrimaryNavItems` in
`primary-nav.ts` (path, label key, icon) and the `/pepites` rule in
`isPrimaryRouteActive`; the Matchs tab would then need to stop lighting on
`/matches/standings` for the new tab to light there.

## Acceptance criteria

- Unit tests: the visitor set, the member set with Curva live and the member
  set with Curva off, in the item lists, the `curvaInBar` rule, and the
  active-state function for each (every `/pepites/*` page, `/curva/*`).
- Browser, French and Arabic (RTL, tab order mirrored), 320, 390 and 1440px,
  light and dark: the five tabs fit with no truncated label, each tab at least
  44px by 44px, nothing past the viewport edge, the right tab lit on
  `/pepites`, `/pepites/classement` and `/curva` for each of the three states.
- The Prospects home has no « Fantasy » back pill for a visitor and keeps it for
  a member with Curva live.
- Measured on real element boxes (not `scrollWidth` alone), against this
  worktree's own dev server on port 5185 in local mock modes: no sign-in, no
  write to production.
- Typecheck, lint, formatting and the tests next to the changed files pass.
