# Phase 3 mobile / Arabic / access review of prototypes

Reviewer: Mobile, Language & Access operator. 2026-10-27. Repo untouched; nothing committed.
Prototypes reviewed (14 files, 7 screens x FR/AR): home, live (match page), player, rank (Fantasy rankings), standings, team, teamnew.
Matrix run: 320x568, 360x740, 390x844 x FR and AR x light and dark (landscape 640x360 and 568x320, light only) = 112 runs, loaded as `file://...?shot=1[&theme=dark]`, `reducedMotion: reduce`.
Method: overflow by bounding boxes (not scrollWidth); tap targets = painted box plus `elementFromPoint` probe of the real hit area (probe capped at 40 px each way, so "81" means "at least 81"); text under 12 px (FR) / 13 px (AR) from computed font-size of every visible text node; contrast = text hidden, viewport screenshot, sRGB pixels of the real background under each text box, worst 3rd-percentile pixel vs the computed text colour (oklch resolved through the browser), elements covered by sticky bars at that scroll are skipped and re-sampled; bidi/RTL from the DOM. Spec: `mobile-spec.md`.
Evidence: `mobile-shots/measure-all.json` (every number), `summary-agg.txt`, `contrast-pairs.json`, `bidi-latin-in-rtl.txt`, `misc.txt`, 112 PNG screenshots (`<file>-<w>x<h>-<theme>.png`; full-page shots show the fixed bottom nav in the middle of the page, that is a screenshot artefact, not a bug), `standings-ar-320-header-zoom.png`. Scripts: `tools/review.js`, `agg.js`, `bidi2.js`, `misc.js`.

## Summary
The prototypes follow the spec well. Zero horizontal overflow of page content, zero text under the floor, zero tap targets under 44 px effective, zero unnamed controls, every page has a localised `<title>`, one `h1`, no heading skips, viewport without `maximum-scale`, Arabic fonts load with the new fallback stack, the pitch is `dir=ltr`, scores/minutes are isolated. Issues below are real but mostly small. Two need a fix before build: the Arabic standings header (R1) and the language prompt sentence (R2).

## What passed (measured)
- Overflow by bounding boxes: 0 elements outside the viewport on all 14 files x 3 widths x light/dark x FR/AR, apart from R5. Landscape 640x360 and 568x320: 0.
- Text size: 0 text nodes under 12 px (FR) or 13 px (AR) on any file, width, theme. Computed FR micro/label = 12 px; AR micro/label = 13 px; AR body 16, meta 14 (as spec 1.2). Club monograms >= 12 px.
- Tap targets: 0 interactive elements under 44 x 44 effective on all files (nav items 63-72 x 62-64, tabs 48 high, chips 44 high, icon buttons now 44). 
- Contrast: all text on `--ui-surface`, page and sunken, in light and dark, passes 4.5:1 except R4 (club fills). Status chips (`.badge.pos/.neg/.live`, injured, double gameweek) pass with the new `-text` tokens.
- Zoom: every viewport meta is `width=device-width, initial-scale=1, viewport-fit=cover` (no `maximum-scale`, no `user-scalable`). `touch-action: manipulation` on `a` and `button`.
- Language/title: `<html lang dir>` correct on every file; `<title>` localised with the pattern `{Page} - BotolaGO` (home keeps the long brand title); one `h1` in the page language; 0 heading level skips; 0 unnamed links/buttons/inputs; 0 images without alt; skip link present.
- Fonts: Arabic body computes to `"Noto Sans Arabic", system-ui, "Segoe UI Arabic", Tahoma, sans-serif`; Noto Sans Arabic and Changa loaded (document.fonts) on all AR pages; French loads Manrope, Changa.
- RTL: the 6 directional icons (`.dir`) have `scaleX = -1` in AR; crests, scores and clock are not mirrored; the Fantasy pitch container is `dir=ltr`, no transform (`team.ar.html`), formation and jerseys unchanged; player names on the pitch are readable (AR names present, `(م)`-style position codes kept). Standings columns line up header-to-data in both languages (same x for every column in both rows).
- Bidi: no score or minute outside an isolate (`bdi dir=ltr`); no Latin word beside Arabic words without `bdi`, other than R2. Scores sit beside their own team and mirror (home right in AR: `home.ar-320x568-light.png`).
- Live announcements: score headline `aria-live="polite" aria-atomic` with a spoken sentence in the page language ("الرجاء البيضاوي 1، حسنية أكادير 1، الدقيقة 63"); no live region on the clock.
- Focus: first focusable element has a 2 px solid outline in all files. Reduced motion: present in `proto.css`; animations off in my runs.

## What I could not check, and why
- Inputs and 16 px fields: no `input`/`select`/`textarea` exists in any prototype (0 found by `misc.js`), so the M1 field rule was not tested. If a search or sign-in prototype appears I will test it.
- Real safe areas and landscape notches: Chromium here has insets 0; R7 is a code finding only.
- Real Android fonts, system font scaling, old WebView, TalkBack speech: no device or emulator (same limit as Phase 1).
- Painted-gap spacing between neighbouring controls (centre-to-centre >= 44): my probe cap (40 px) and horizontally scrolling chip strips (strips measured 481-577 px wide inside 296 px) make pair distances unreliable; I did not claim it. The chip strips scroll by design and I did not test their scroll cue.
- Only the light theme in landscape; only the first screenful states of each page (no empty, error, loading or sponsor-off state: `?sponsor=off` not run; `?state=` not run).
- Sticky table header behaviour while scrolling was measured at scroll position 0 (the budget counts what is fixed/sticky at the top/bottom edge); a bar that only sticks after scrolling would show in my run only if it already touched the edge.
- Mixed-name stress: Arabic names are short in all prototypes; long real Arabic player names and 2-line club names at 320 were not available.
