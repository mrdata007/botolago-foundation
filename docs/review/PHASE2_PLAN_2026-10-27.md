# BotolaGO – Phase 2 plan (27 Oct 2026)

Built from the approved Phase 1 audit
([`PHASE1_AUDIT_REPORT_2026-10-27.md`](PHASE1_AUDIT_REPORT_2026-10-27.md)).
Codes such as S4 or F2 point to findings in that report.

## How every batch runs

1. The Builder works on its own branch, never on the live version.
2. A separate Tester checks it: it works, nothing else broke, French and Arabic, a 320px phone, no extra API calls.
3. Builder and Tester loop, at most 3 rounds. Then the Lead reviews it.
4. The owner gets a plain report and decides. Nothing is merged, published in Lovable, applied to the database or deployed without the owner's yes.
5. Batches that change the database run one at a time (AGENTS.md "one writer at a time"). Screen batches follow the AGENTS.md screen rules: a written brief first, before/after screenshots, French and Arabic, and a draft pull request.
6. Dead code and unused packages that a batch touches are removed as part of it.

## Batch 0 – Stop the call waste and switch to SportAPI (emergency, in progress)

Branch `claude/rapidapi-call-reduction`.

- **A – Call waste.** Stop re-downloading line-ups, timeline and stats on every live update; fetch them once at full time, and the timeline only when the score changes. Make the manual GitHub jobs count their calls. Make the safety stop stay on when the counter can't be read. (S1–S3, measured counts)
- **A2 – SportAPI switch.** The same app talks to SportAPI instead, through one setting. Same data, same IDs (checked on 27 Oct).
- **Owner steps after review:**
  1. Subscribe to a SportAPI plan.
  2. Create a new key.
  3. Put the key and the host in the Supabase secrets.
  4. Deploy one function.

  The Builder's report will list the exact steps.
- **Plan size until the Sofascore reset:** with the waste fixed, about 150–200 calls on a match day, so a plan of about 5,000 a month covers it with room to spare.

## Batch 2 – Fantasy fairness before any sponsored challenge

Server and database only; no screen changes.

- A prize period is retried until it is really awarded, never silently skipped (F2).
- A match moved earlier closes the deadline at once (F7).
- Prizes skip hidden test accounts and use the leaderboard's tie-break (F6).
- A missing rating raises an alert after 3 days. The rating check window becomes 21 days. The owner's rule for "never rated" is applied (F4).
- Season and monthly prize for GW1–4, coded to the owner's decision (F3).
- The captain rule, as the owner decides (F10). The prize rules state "rating = first full Sofascore rating" (F5).
- A read-only copy of the exact scoring code in the database, saved in the project (F15).
- One broken team no longer blocks locking the whole gameweek (F14).

Needs: owner decisions 2–5 from the Phase 1 report, then migrations applied by the owner.

## Batch 3 – BSD for match data

- BSD becomes the source of fixtures, live scores, live minute, line-ups, goals, cards and substitutions. The live goal timeline is saved while each match is on.
- Sofascore on RapidAPI only fetches Fantasy ratings and team stats, once per finished match.
- If BSD stops answering, live scores switch to RapidAPI automatically.
- An alert goes out the same day if ratings come back empty or calls start failing.
- Leftover Sportmonks/Flashscore code on this path is removed (S12, partly).

Needs: owner approval, then a migration and a function deploy.

## Batch 4 – Arabic from the first screen

- The language choice is remembered in a cookie, so the server sends Arabic, right-to-left, at once (M2, S6). This also removes the second data reload.
- The first-visit language pop-up no longer blocks pages opened from Google or WhatsApp (U14).

Needs: the owner's OK on the cookie (decision 9).

## Batch 5 – Speed

- Visitors who aren't logged in no longer download login, two-step sign-in or Fantasy code (S4).
- Public pages are kept for 30–60 seconds at Cloudflare, so a derby rush doesn't rebuild each page for every fan (S7).
- The live match list is cached for 10–15 seconds in front of the database (S8).
- News pictures in phone sizes (S13); the Arabic font is preloaded for Arabic readers (M9c).

## Batch 6 – Fake accounts and logins

- Anti-bot check (Cloudflare Turnstile) on sign-up and password reset (C11, F8).
- Email clean-up (dots and "+" aliases) and a block-list of throwaway email domains.
- A limit on leagues per person. A one-person-one-prize check at payout.
- Passwords 10+ characters plus a leaked-password check in Supabase (C8). Limits on testing usernames (C10).

Needs: the owner sets up Turnstile and the dashboard settings (decision 6).

## Batch 7 – Fantasy ease of use (after the Phase 3 designs)

Auto-fill a first squad (U2), a Fantasy tab bar (U15), a simpler Matches
header (U3), one style for empty/error/loading screens (U5), and a shorter
sign-up (U13). These are screen redesigns, so they follow the approved
Phase 3 designs.

## Batch 8 – Tidy-up and safety

- Retire finished one-off GitHub jobs; split production keys (C3).
- Update risky packages: `zod`, the MCP connector, `sanitize-html` (C1).
- Delete the remaining Sportmonks/Flashscore dead code (S12). The player-mapping tool stays if staff still use it.
- Remove old design components (U6). Add a script policy in report-only mode first (C2). Merge the Morocco-date copies (C7).

Needs: the owner's list of jobs to retire (decision 7).

## Batch 9 – Correcting scores after a gameweek is final

A reviewed 72-hour correction process: recalculate, re-rank, re-check prizes,
send a notice, keep an audit record (F1). This is large; it is designed in
Batch 2 and built here, before the first sponsored challenge pays out.
