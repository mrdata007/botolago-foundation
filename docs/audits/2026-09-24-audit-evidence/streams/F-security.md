## Findings (ordered by severity)

### S-01 — Open redirect after password sign-in (`/auth/login?next=…`) on the LIVE site; the repo fix is itself bypassable
- Severity: **P1**  Confidence: **VERIFIED (code path on live build; final hop not executed because no account may be used)** / repo bypass **VERIFIED by execution**
- Location: live `https://botolago.com/assets/auth.login-CrvznNXP.js`; repo `src/routes/auth.login.tsx:31-35` (`sanitizeNext`) and `:98-101` (`window.location.href = next`)
- Evidence:
  - Deployed login chunk: `{next:n}=y.useSearch(), … B=e=>{if(n&&e){window.location.href=n;return}…` — `n` is the raw `next` search param. No `startsWith("/")` guard exists in any deployed chunk (`grep` over `index-BQJLG-CU.js`, `auth-*.js`).
  - Playwright on live `/auth/login?next=https%3A%2F%2Fevil.example`: the "Créer un compte" link renders as `/auth/register?next=https%3A%2F%2Fevil.example` — the value is NOT stripped by the deployed route's search validation (`probe-results.json → login_next_https://evil.example`). `/auth/register?next=…` propagates it back to `/auth/login?next=https%3A%2F%2Fevil.example` likewise.
  - Therefore on the live build: a password sign-in with a completed profile executes `window.location.href = "https://evil.example"`. OAuth path is safe (it goes through `getCallbackUrl → sanitizeAuthCallbackNext`).
  - Repo HEAD (`3dca4cd`, 2026-09-21, not yet deployed) added `sanitizeNext` = `startsWith("/") && !startsWith("//")`. Executed check (node): `"/\\evil.example"` → ACCEPTED → browser resolves to `https://evil.example/`; `"/\t/evil.example"` → ACCEPTED → `https://evil.example/`. The project's own `src/lib/auth-callback.ts` comment documents exactly this bypass and provides the correct function (`sanitizeAuthCallbackNext`), which `auth.login.tsx` does not use.
- Reproduction (non-destructive): open `https://botolago.com/auth/login?next=https%3A%2F%2Fevil.example`; inspect the register link. (Do not sign in.)
- Impact: phishing hop that starts on the real domain right after a real sign-in; also `next` accepted on `/auth/mfa-challenge` (`window.location.href = next`, line 90) — that route does use the safe sanitizer.
- Fix (S): in `auth.login.tsx` replace `sanitizeNext` with `sanitizeAuthCallbackNext` from `@/lib/auth-callback`; prefer `navigate({ to: next })` over `window.location.href`; add a regression test with `/\evil.example`, `/%09/evil.example`, `/\t/evil.example`; publish. Also add an `auth.login.test.ts` mirroring `auth-callback.test.ts`.

### S-03 — Unauthenticated, expensive RPCs time out under light load (home page data 500s); no per-IP rate limit in front of PostgREST
- Severity: **P1** (availability / DoS amplification)  Confidence: **VERIFIED**
- Location: `api.news_feed`, `api.football_home_matches` (anon-executable, `STABLE SECURITY DEFINER`); called by the home page on every visit.
- Evidence: Playwright home load at 16:36 UTC: `POST /rest/v1/rpc/news_feed` → 500, `POST /rest/v1/rpc/football_home_matches` → 500 (console error). `curl GET …/rpc/news_feed?p_language=fr&p_limit=50` → `{"code":"57014","message":"canceling statement due to statement timeout"}` HTTP 500 in 9.5 s (two samples). Two read-only catalog queries via the Supabase MCP also hit the 60 s tool timeout in the same window. The coordinator reports real visitors got 500s 16:20–16:45 UTC while several audit streams ran at ≈1 rps each.
- Interpretation: a handful of low-rate anonymous clients is enough to push the production Postgres over its statement timeout; the anon key allows anyone to call these RPCs directly, unlimited by Cloudflare's WAF (the WAF blocked an SQLi-shaped query string but not volume). This is an unauthenticated resource-exhaustion vector, and it is also why the home page shows errors.
- Fix (M, coordinate with backend/perf streams): cache `news_feed`/`news_home_modules`/`football_home_matches` results (materialised view or short TTL table refreshed by pg_cron; or SSR + edge cache with `s-maxage`), add covering indexes, put a Cloudflare rate-limit rule on `/rest/v1/rpc/*` per IP, and consider a Supabase compute upgrade. Return a cached response instead of 500 on timeout.

### S-09 — `trustForwardedHost: true` on the MCP routes: attacker-controlled `X-Forwarded-Host` is reflected into OAuth resource metadata (cacheable) and `WWW-Authenticate`
- Severity: **P3**  Confidence: **VERIFIED**
- Location: `src/routes/mcp.ts`, `src/routes/[.mcp]/list-tools.ts`, `[.mcp]/invoke-tool/$tool.ts`, `[.well-known]/oauth-protected-resource.ts` (all `trustForwardedHost: true`, auto-generated by `@lovable.dev/mcp-js`)
- Evidence: `curl https://botolago.com/.well-known/oauth-protected-resource -H "X-Forwarded-Host: evil.example"` → `{"resource":"https://evil.example/mcp",…}` with `cache-control: public, max-age=300` and `vary: Host` (not `X-Forwarded-Host`). `curl /mcp -H "X-Forwarded-Host: evil.example"` → `www-authenticate: Bearer realm="mcp", resource_metadata="https://evil.example/.well-known/oauth-protected-resource"`. - Fix (S): set `trustForwardedHost: false` (the site has a fixed canonical host) or have the edge strip client-supplied `X-Forwarded-Host`; drop `public` caching on the metadata route.

## Things done well (verified)
1. **API surface is RPC-only and correctly locked.** PostgREST exposes only `api`; anonymous OpenAPI is refused ("Secret API key required"); the four `api.my_*` views return 401 for anon; `api.live_fixture_updates` is the only anon-readable table (RLS + force RLS, contains only live fixture data). No anonymous PII readable. All 220 `api` functions: 44 anon-executable (all `STABLE`, read-only, `search_path=''`), 90 authenticated-only, 86 service-role-only; 0 SECURITY DEFINER functions without `search_path` in `api`, `app`, `app_private`.
2. **Admin gating is server-side.** Anonymous `GET /admin/users` returns a generic shell ("Vérification de l'accès… côté serveur"), no admin data in HTML; the `_serverFn` calls return `unauthenticated/missing_token`. `api.get_my_staff_context` requires an active principal, verified e-mail, an enrolled TOTP factor, `aal2`, a session ≤15 min old for sensitive actions, and pending-revocation awareness; dual-control (`admin_request_approval`/`approve`/`execute_approved_platform_admin`) and `app_private.admin_audit_events` exist; `admin_list_users` masks e-mails (`admin_mask_email`) and escapes LIKE wildcards.
3. **Fantasy IDOR controls.** `fantasy_assert_owner` on every team mutation; private-league standings require active membership; invite codes are 128-bit random hex, stored only as SHA-256 digests with a 4-char hint; idempotency keys per user.
4. **Article HTML trust boundary.** Only two `dangerouslySetInnerHTML` sites; both render output of the server-side sanitizer whose result is HMAC-bound (`app_private.verify_editorial_content_mac`) so a client cannot submit unsanitised HTML; allow-list is tight (`https` only, no `on*`, no iframes, external links get `rel="nofollow noopener noreferrer"`). ElBotola import stores only an escaped summary plus a link, never provider HTML. No HTML in i18n strings.
5. **Uploads.** `news-media-upload` refuses before reading the body unless the caller's staff context grants `editorial.write|publish`, sniffs magic bytes against the declared MIME, caps at 10 MiB, random object names, `upsert: false`, and deletes the object if registration fails. Buckets: `avatars` private with per-user path policies; `news-media`/`football-media` public by design with MIME allow-lists and size limits.
6. **Edge functions.** Ingestion functions require `verify_jwt` plus a timing-safe shared `x-botolago-ingestion-key`; cron-woken functions verify a database-held 256-bit scheduler token; one-click unsubscribe uses a 192-bit token, GET never unsubscribes, body capped at 1 KiB, token never logged.
7. **Auth flows.** OAuth/e-mail callback scrubs tokens from the URL before any async work and uses a correct same-origin `next` sanitiser; guest flag handling is storage-safe; sign-out records a revocation event and clears app localStorage keys; banned accounts are signed out on visibility change.
8. **Secrets hygiene.** `bun run backend:secrets:check` passes; `.env.production` holds only the publishable key; `.env` files never tracked; git-history hits for `sb_secret_`/`eyJ…` are test fixtures and pattern text only; workflows `::add-mask::` every secret and grep evidence directories for leaks before upload.
9. **Supply-chain response.** The eslint-loader incident was analysed to the exact merge commit, removed, and turned into a CI guard (`check-config-integrity.mjs`, R1–R6) that runs before `bun install`, plus a 24 h `minimumReleaseAge`.
