# BotolaGO Admin MCP

Scope: a standalone MCP service for Codex and ChatGPT, using the existing
Production V2 admin API contracts. No production database changes or deployment.

## Preserve

The existing website and consumer MCP remain intact. Admin authority remains
the signed-in user's canonical staff state, verified email, MFA/AAL2,
permission checks, recent authentication, idempotency, dual control and audit.
The current OAuth consent screen and admin shell informed the sign-in flow.

## Improvements

Expose the staff-facing admin RPCs and editorial/media Edge Functions through
a dedicated Streamable HTTP MCP. Its OAuth authorization server signs staff in
with Supabase password authentication and the enrolled second factor before
issuing connector credentials. Supabase's consumer OAuth code exchange starts
an AAL1 session, so it cannot supply the admin assurance this service needs.
The dedicated service stores encrypted user sessions locally and never returns
Supabase credentials through tools. It never uses a service-role key.

## Acceptance criteria

- Codex and ChatGPT discover OAuth metadata, register clients, authorize with
  PKCE, and connect to `/mcp` on the same service.
- Sign-in and MFA happen only in the browser; credentials never enter chat.
- A connection cannot execute as another user or acquire additional authority.
- Read/write requests use the real AAL2 user token and existing backend gates.
- Sensitive actions can request browser reauthentication after the existing
  15-minute window; refreshing connector tokens does not reset that window.
- No arbitrary SQL, RPC, Edge Function, service worker, or server-side URL fetch.
- Schema generation is reproducible from the checked-in database types.
- Test OAuth replay/client/resource isolation, encryption, CSRF, MFA refusal,
  refresh/revocation, catalog coverage, validation and mocked end-to-end MCP.
- The new browser forms work at phone and desktop widths in French and Arabic
  with RTL, visible labels, keyboard access and responsive layout.
- Deliver a draft PR with tests and setup instructions. Deployment needs the
  owner's approval as required by AGENTS.md.
